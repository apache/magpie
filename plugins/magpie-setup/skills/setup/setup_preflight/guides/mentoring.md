# 🐦 Magpie here — your newcomer-mentoring sidekick

A one-minute tour, then straight back to what you asked for.

## 🔄 The typical flow

1. 👋 **Welcome** a first-time contributor with project guidance — *"welcome the newcomer on PR 123"*
2. 🔎 **Sweep** the backlog for newcomer-ready tasks — *"find good first issues"*
3. ✍️ **Author** one self-contained beginner issue — *"draft a good first issue for this small task"*
4. 📖 **Explain** an existing issue in beginner terms — *"explain issue 123 to a newcomer"*

Magpie drafts first. Comments, new issues, and labels require explicit maintainer confirmation.

## ⚙️ Configure it

Set up the project context before using these skills:

- 🗂️ **Project** — `project.md` identifies the repository and project context for every mentoring skill
- 🏷️ **Good first issues** — `good-first-issue-config.md` and `issue-tracker-config.md` are required for sweep and author
- 💬 **Optional guidance** — `mentoring-welcome-config.md` controls welcomes; `newcomer-issue-explainer-config.md` shapes explanations

Configure personally with `/magpie-setup:setup config`.
Project adoption with `/magpie-setup:setup adopt` is a maintainer decision.

## 💬 Just ask

Talk to Magpie in plain language:

- *"welcome the first-time contributor on issue 123"*
- *"find newcomer-ready issues in the backlog"*
- *"which issues need changes before getting a good first issue label?"*
- *"draft a good first issue from this small task"*
- *"explain issue 123 with the files to read and what done looks like"*

Security-sensitive threads are not suitable for these newcomer workflows.
Contributors who were already welcomed, and threads already handled, are skipped.

## 🎨 Make it yours

Describe how your project's mentoring should work:

- *"make newcomer explanations include a first test to run"*
- *"use our contribution guide when drafting welcome messages"*

Review the proposed override before using it.
Useful to others? Ask *"upstream this change to Magpie"* to prepare a reusable contribution for review.
