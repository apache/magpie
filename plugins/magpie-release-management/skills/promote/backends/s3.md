# Promotion backend — `s3`

The render's `command_block` moves the RC prefix to the release prefix (`aws s3 mv s3://<bucket>/<key-prefix>/<version>-rc<N>/ s3://<bucket>/<key-prefix>/<version>/ --recursive`)
and verifies it (`aws s3 ls`).
Both URIs are the rendered `staging_url` / `target_url` rewritten as `s3://<bucket>/<key>/`, so any key prefix in the template is kept.
A held convenience artefact staged in the RC prefix gets an `--exclude` for itself, its `.asc` and its `.<digest>` files (one per `digest_set` entry) on that `aws s3 mv`, so it stays behind;
see [`../convenience-artefacts.md`](../convenience-artefacts.md).

`<bucket>` is read from `release_dist_url_template` (the S3 bucket name component): an `s3://<bucket>/…` URL,
or an `https://<bucket>.s3.<region>.amazonaws.com/…` (virtual-hosted) / `https://s3.<region>.amazonaws.com/<bucket>/…` (path-style) URL.
A template the bucket cannot be read from is refused; fix the template in `release-management-config.md`.

The promotion event is the `aws s3 mv`; the mirror note's one-hour clock starts there (CDN cache, not mirrors).
